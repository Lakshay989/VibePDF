# Phase 4 — Content editing (decoupled steps)

> Goal (per `docs/05_ROADMAP.md`): edit existing text without breaking
> the document. Add new text, images, and decorations. **This is the
> hardest phase.** It's where the product earns the "elite" label.

## Acceptance demo (from roadmap)

- Open `tests/fixtures/acceptance/p4-edit-typo.pdf`. Edit the typo. Save. Diff against Acrobat's edit of the same document — text in same position, same font, no visual drift.
- Add a watermark to a 50-page PDF in under 2 seconds.
- Apply Bates numbers across three merged PDFs starting at `ABC000001` — confirm sequence is correct on every page.

## Spec coverage

`P4-EDIT-001` through `P4-EDIT-012` (12 spec lines). Plus 3 infrastructure steps for the text engine.

## Hard rule (from the roadmap)

Text editing is **intrinsically lossy** when fonts aren't embedded.
Be honest with the user; never silently substitute and pretend the
result is identical.

## Track A — Text engine infrastructure

### P4.A1. `[~]` Text run extraction + bounding boxes
- **Spec:** infrastructure for **P4-EDIT-001** (edit existing text) / P4-EDIT-004.
- **Touches (new):** `src-tauri/src/pdf/text_extract.rs`, `src/ipc/text-runs.ts`;
  (modify) `actor.rs` (`ReadTextRuns` read-only query), `commands/pdf.rs`
  (`pdf_extract_text_runs`), `lib.rs`, `mod.rs`.
- **What:** Walk each page's **PDFium text page-objects** (one ≈ one show
  operator = the natural edit unit) via the pdfium-render *high-level* API (no
  unsafe FFI) and emit a `TextRun { text, bbox[4] PDF-pts, fontName, embedded,
  fontSize, color #rrggbb, transform[6] }`. **Read-only**: runs on the *live*
  `PdfDocument` under the `PDFium` lock (like `render_page`), **not** the cos
  byte path — text decoding is PDFium's job. Subset tags (`ABCDEF+`) stripped;
  `embedded` surfaced to feed A2's font-fallback. The IPC is exposed for **P4.B1**
  to hit-test a click to a run; **no UI consumes it yet** (B1 wires it).
- **Test:** `src-tauri/tests/text_extract.rs` (extracts runs from `hello.pdf` with
  sane page-space bbox + populated font/size/colour; out-of-range page errors;
  stable across `links.pdf`/`forms.pdf`) + `text_extract.rs` unit (subset-tag
  strip, hex) + `src/ipc/__tests__/text-runs.test.ts`.
- **Acceptance:** infra step, no UI — the Rust test *is* the acceptance (it
  extracts the expected run(s) from `hello.pdf`). `check` + `test` (312) +
  `test:rust` green. No write path → no artifact.
- **`[~]`** because it's read-only infra with no user-facing surface yet; flips to
  `[x]` once B1 consumes it (or on an eyeball of logged runs, if wanted).
- **Depends on:** P2.A1, P2.A3.

### P4.A2. `[~]` Font fallback resolver
- **Spec:** P4-EDIT-002
- **Touches (new):** `src-tauri/src/pdf/font_resolver.rs`, `src/app/FontFallbackBanner.tsx`,
  `src/app/use-font-report.ts`, `src/ipc/fonts.ts`; (modify) `text_extract.rs`
  (`collect_document_fonts`), `actor.rs` (`ReadFontReport` read-only query),
  `commands/pdf.rs` (`pdf_read_font_report`), `lib.rs`, `mod.rs`, `PdfViewer.tsx`.
- **What:** When the original font isn't embedded and isn't on the system, choose the closest match from a fallback stack (Helvetica → Arial → sans-serif), warn the user **once per document**, and offer to re-flow the affected run. The resolver is **pure** (`resolve_font` + `build_font_report`); the only side effect is a one-time std::fs scan of the OS font dirs (`load_system_fonts`, `OnceLock`-cached) — **no new dependency**. "Installed on the system" is a normalized file-stem heuristic; bias = **warn when unsure** (never silently substitute). Base-14 faces are always treated as safe. The `ReadFontReport` actor query walks the live `PDFium` doc (A1's read path) to collect distinct fonts.
- **Acceptance:** Open a PDF with a custom font referenced but not embedded → banner appears once, naming each substitution, with a "Re-flow" affordance (disabled until P4.B1 — the *offer* ships now, the *action* with text editing). Rust test is the deterministic gate.
- **Test:** `src-tauri/tests/font_fallback.rs` (hand-built non-embedded Calibri → fallback; `hello.pdf` base-14 → no fallback; cross-doc invariants) + `font_resolver.rs` units + `src/ipc/__tests__/fonts.test.ts` + `src/app/__tests__/font-fallback-banner.test.tsx`.
- **`[~]`** because the re-flow *action* (and the banner eyeball) lands with B1; resolver + warning are shipped + gated. `check` + `test` (318) + `test:rust` green. No write path → no artifact.
- **Depends on:** P4.A1.

### P4.A3. `[~]` Two-phase redact-and-reflow primitive — **shipped EDIT-only**
- **Spec:** infrastructure for P4.B1/B2 (and P6.C1 redaction)
- **Touches (new):** `src-tauri/src/pdf/reflow.rs`; (modify) `mod.rs`.
- **What (as shipped):** `replace_text_run(bytes, page, run_index, new_text) -> bytes`
  rewrites a run's text **in place** via `PDFium`'s `FPDFText_SetText`, preserving
  font/size/colour/matrix. The project's first `PDFium`-mutation write: it mutates a
  *throwaway* doc loaded from the input bytes (never the live doc — content mutation
  SIGSEGVs at teardown), serializes, and `ReplaceTextRunEdit` swaps the live doc with
  a `RestoreDocEdit` snapshot as the inverse. `run_index` matches A1's ordering so B1's
  hit-test maps straight through. No actor/IPC/UI yet (B1 wires it).
- **⚠️ Scope cut — the *redact* half is deferred.** The planned delete (P4-EDIT-004),
  true redaction (P6-SEC-010) and fallback-font *recreate* all need object **removal**,
  but our bundled `PDFium`'s `FPDFPage_RemoveObject` **SIGSEGVs** (diagnosed to the FFI
  call; same family as the `resize_pages` reload crash). Per the 2026-06-26 decision,
  A3 ships edit-only; removal-based ops wait on a non-crashing path (lopdf
  content-stream surgery — see `BACKLOG.md`). Editing a non-embedded-font run still
  succeeds (font ref kept; A2 already warned); baking the substitute face needs removal.
- **Test:** `src-tauri/tests/reflow.rs` (replace preserves position + changes text via
  A1 re-extraction; round-trips through `PDFium`; edits a non-embedded font; bad
  page/run index errors; `ReplaceTextRunEdit` inverse restores; `#[ignore]` artifact).
- **`[~]`** because it's read-for-B1 infra with no UI, *and* the redact half is unbuilt.
  `check` + `test` (318) + `test:rust` (reflow 5 +1 ignored) green. Artifact:
  `/tmp/vibepdf-verify.pdf` (edited `hello.pdf` → "Hello, World!").
- **Depends on:** P4.A1, P4.A2.

### P4.C2. `[~]` Edit existing image — **move/resize/rotate/delete + replace (C2b)**
- **Spec:** P4-EDIT-006
- **Touches (new):** `src-tauri/src/pdf/image_extract.rs` (locate), `image_edit.rs`
  (transform + delete + Edit impls), `src/view/image-edit-layer.tsx`, `src/ipc/image-edit.ts`,
  `src/tools/image-edit/matrix.ts`; (modify) `mod.rs`, `actor.rs` (`ReadImages`/`TransformImage`/
  `DeleteImage`), `commands/pdf.rs` (3 commands), `lib.rs`, `tool-store` `ToolId`,
  `MarkupToolbar.tsx`, `PageVirtualizer.tsx`; (fix) `cos.rs` `append_page_content`.
- **What:** **Edit Image** tool → click an image (located via PDFium, A1-style) → a selection
  box: drag the body to **move**, drag a corner to **resize**, **⟳ 90°** button to rotate,
  **Delete** button to remove. Move/resize/rotate all compute a new placement **matrix** the
  backend applies via PDFium **`reset_matrix`** (a mutate-in-place FFI that *works* — the
  Risk-#1 validation; only `remove_object` crashes). Delete splices the image's `Do` at the
  lopdf level (B3 pattern), verified by re-extraction (count + bbox match). Undoable.
- **⚠️ Found + fixed a latent bug:** C1/B2's `append_page_content` produced content streams with
  no leading separator, so a page ending `…ET` fused with the appended `q` into a bogus `ETq`
  when lopdf re-decoded the `/Contents` array (PDFium had masked it). This corrupted multi-image
  delete (image cms composed). Fixed by prepending `\n` to appended content.
- **Replace (C2b):** `image_edit.rs::replace_image` embeds the new PNG/JPEG (`embed_image`) and
  overwrites the `XObject` the selected image references **in place** (resource name + `cm` + `Do`
  untouched — only the pixels change, so no `/Resources` edit / copy-on-write). Verified by
  re-extraction (count + every bbox unchanged). `ReplaceImageEdit` + `ReplaceImage` actor msg +
  `pdf_replace_image` (reads the file) + `replaceImage` IPC + a **Replace** button (file dialog)
  in the selection toolbar. Placement preserved; the new image fills the old box (aspect may
  differ → resize via the handles).
- **Scope:** move/resize/rotate/delete/replace. Resizing a *rotated* image resets its rotation
  (axis-aligned `rectToMatrix`); 90° rotation only.
- **Acceptance (in-app):** add an image (C1), Edit Image → click it → move/resize/rotate-90/
  **replace** (pick a file)/delete each reflect on the canvas; Cmd/Ctrl+Z undoes each.
- **Test:** `tests/image_edit.rs` (transform moves/resizes/rotates [Risk-#1 no-SIGSEGV]; locate;
  delete + **2-image ordinal correctness**; out-of-range; actor transform+delete+undo) +
  `tests/image_replace.rs` (swap preserves placement + changes XObject dims; keeps alpha;
  preserves other images; out-of-range; actor replace+undo) + `matrix.test.ts` +
  `image-edit.test.ts` + `image-edit-layer.test.tsx`. Both with `#[ignore]` artifacts.
- **`[~]`** pending the in-app eyeball. `check` + `test` (346) + `test:rust` (image_edit 7,
  image_replace 5, +ignored) green. Artifact: `/tmp/vibepdf-verify.pdf`.
- **Out of scope:** aspect re-fit on replace, free-angle rotate handle (90° only), images in Form
  XObjects / shared across pages, crop, opacity. ("Original data preserved" holds trivially —
  move/resize/rotate/delete never touch pixels.)
- **Depends on:** P4.C1.
