# Phase 2 — Page operations (decoupled steps)

> Goal (per `docs/05_ROADMAP.md`): move, copy, delete, merge, split,
> extract, rotate pages — and finally **save real PDFs as output**.
>
> Phase 2 is also where the project earns the right to mutate bytes.
> Every write path lands behind the document actor and round-trips
> through PDFium before returning success — see [[B1]] in `steps/P1.md`.

## Acceptance demo (from roadmap)

- Open `tests/fixtures/acceptance/p2-multi.pdf`, delete page 3, insert a blank, rotate page 5 by 90°, save. Re-open in Adobe Acrobat: changes are visible, file is not corrupt.
- Merge 5 PDFs from `tests/fixtures/acceptance/p2-merge-*.pdf`. Form fields and bookmarks survive.
- Split a 100-page PDF into 10 files. Each file opens cleanly.

## Spec coverage

`P2-PAGE-001` through `P2-PAGE-010` (10 spec lines). Plus 3 infrastructure steps (save, autosave, undo/redo) with no `P2-PAGE-*` ID.

### P2.A1. `[x]` Save button
- **Status:** Done. Atomic temp+rename, `.bak` rotation, round-trip verify,
  dirty-flag no-op. `check` + `test` (70/70) + `test:rust` (incl. 3
  `save_noop` cases) green. Human verified the saved artifact opens cleanly in
  Preview + Acrobat + a third reader, and re-opens in VibePDF itself (clean
  GUI dev session, no panics; also exercised a real 4-page statement).
  Deviation from the doc below: the Cmd/Ctrl+S binding lives in a new
  `src/app/use-save.ts` hook (matching the `use-file-open.ts` pattern) rather
  than inline in `App.tsx`; save logic lives in `pdf/document.rs` (which
  `docs/04` already allocates to "Open, save, metadata") rather than a new
  `pdf/save.rs`.
- **Spec:** infrastructure
- **Touches (new):** `src-tauri/src/commands/save.rs`, `src/ipc/save.ts`
- **Touches (modify):** `src/app/App.tsx` (Cmd/Ctrl+S binding), `src-tauri/src/pdf/actor.rs` (`Message::Save { path }`)
- **What:** Write the current PDFium document to disk. If `path` matches the original, rotate the previous file as `<name>.bak` (kept for one save cycle only). Round-trip the saved bytes through PDFium before reporting success; reject on read-back failure.
- **Acceptance:** Open hello.pdf → save → file size and SHA-256 unchanged (no-op save is a no-op). Edit (via a later step) → save → re-open in PDFium externally, no parse errors.
- **Test:** `src-tauri/tests/save_noop.rs` — open, save, assert byte-identical (or at least PDFium-identical after canonicalization).
- **Depends on:** P1.B1 (real actor).

### P2.A2. `[~]` Auto-save + crash recovery

## Track B — Single-page operations

### P2.B1. `[~]` Rotate page(s)
- **Status:** Landed — the first real edit. `RotateEdit: Edit<PdfDocument>`
  (`pdf/rotate.rs`) sets PDFium `/Rotate`, integrates with undo (A3) + dirty
  (A1/A2); actor `RotatePages` message; `pdf_rotate_pages` command; thumbnail
  right-click `RotateMenu` with live thumbnail refresh (cache-invalidate +
  re-render) and Undo-button sync. `check` + `test` (81/81) + `test:rust`
  (rotate.rs: 4 — persist/undo/redo/atomic-on-error) green. `[~]` not `[x]`
  until the human confirms `/tmp/vibepdf-verify-rotated.pdf` (also on the
  Desktop) renders rotated in Acrobat + Preview + a third reader.
- **Surfaced + fixed a real concurrency bug:** PDFium isn't thread-safe across
  documents (page-ops/save/close raced → SIGABRT/SIGSEGV). Unified all PDFium
  FFI under one process-global `PDFIUM_LOCK` (was render-only), close the
  actor's doc under it, and run the Rust tests single-threaded. See `docs/04`.
- **Deferred (BACKLOG):** live **main-view** preview of edits (PDF.js updates
  on save/reopen only) + undo/redo-driven view refresh — the shared
  "edit-preview pipeline" for all of B2–B5.
- **Spec:** P2-PAGE-001
- **Touches (new):** `src-tauri/src/pdf/rotate.rs`, `src/tools/rotate/`
- **Touches (modify):** `src/panels/ThumbnailPanel.tsx` (context-menu entry)
- **What:** Rotate single page, range, or all pages by 90° / 180° / 270°. Persisted as PDFium `/Rotate` on the page dict, not a viewer transform.
- **Acceptance:** Rotate page 1 of hello.pdf 90° → save → open externally in Preview.app → page renders rotated. Reopen in VibePDF → rotation persisted.
- **Test:** `src-tauri/tests/rotate.rs` — rotate, save, re-open, assert `/Rotate` on page 0.
- **Depends on:** P2.A1, P2.A3.

### P2.B2. `[~]` Delete page(s)
- **Status:** Landed. `DeleteEdit: Edit<PdfDocument>` (`pdf/delete_page.rs`)
  deletes via `PdfPage::delete`; its inverse stashes the removed pages in a
  holding doc (bytes) and re-imports them → undo restores content **and**
  order. Actor `DeletePages`; `pdf_delete_pages`; thumbnail context-menu
  "Delete page" + Delete/Backspace key; inherits live preview + autosave.
  `check` + `test` (85/85) + `test:rust` (delete_page: 5 + the reference-
  integrity canary) green. `[~]` until the human checks
  `/tmp/vibepdf-verify-deleted.pdf` (also on Desktop) in Acrobat + Preview +
  a third reader, and confirms the GUI flow (delete/undo/live preview).
- **Reference integrity — verified, with a documented limit.** Surviving
  internal links/bookmarks/dests track renumbering automatically (PDF
  destinations are indirect object refs, not indices) — proven by a test on
  `links.pdf` (delete page 2 → page-1 link still targets page 3). What we
  **cannot** do via pdfium-render (read-only outline/link API): clean up
  references *to* a deleted page, or fix index-based refs → BACKLOG (needs
  dict-level access, e.g. `lopdf`; same gap gates P2-PAGE-002 reorder).
- **UI scope:** single-page delete (backend takes `Vec` for future multi-select).
- **Spec:** P2-PAGE-003
- **Touches (new):** `src-tauri/src/pdf/delete_page.rs`
- **Touches (modify):** `src/panels/ThumbnailPanel.tsx` (Delete key handler)
- **What:** Remove the page from the page tree, renumber, update link/bookmark/named-destination references that point to surviving pages.
- **Acceptance:** Delete page 3 of a 5-page doc with an internal link to page 4 → save → re-open → link now targets the new page 3.
- **Test:** `src-tauri/tests/delete_page.rs` — assert page count drops; assert internal links rewritten.
- **Depends on:** P2.A1, P2.A3.

### P2.C3. `[~]` Split (4 modes)
- **Status:** Landed. `pdf/split.rs::split_document` reduces every mode to a
  list of contiguous 0-based page groups, then writes one file per group via
  the shared `extract::write_subset_pdf` (refactored out of C2 — atomic +
  round-trip-verified per file). Output files: `{stem}-NNN.pdf` in a chosen
  directory. **Read-only on the source** — no undo/dirty. Actor
  `SplitDocument`; `pdf_split_document`; a mode-picker **SplitDialog**
  (`tools/split/split-points.ts` parser for mode b) + a native directory
  picker, triggered from the viewer toolbar ("Split…"). `check` + `test`
  (117/117) + `test:rust` (split: 6) green. `[~]` until the human checks
  `~/Desktop/vibepdf-verify-split-00{1,2,3}.pdf` in Acrobat + Preview + a
  third reader.
- **Notes:** modes — (a) every N, (b) split-before 1-based pages, (c) greedy
  by-size (serialize-probe; approximate, never drops a page), (d) top-level
  bookmarks (read-only outline via PDFium — *no* lopdf needed). A split that
  would yield < 2 files is reported as an error rather than emitting one
  copy. By-size re-serializes per page (O(n²)) — fine for one-shot; noted in
  BACKLOG. New fixture `bookmarks.pdf` (6 pp, 3 top-level bookmarks → pages
  0/2/4). Cross-split reference integrity (dangling links/dests) is the same
  lopdf wall as B2/C1 — out of scope.
- **Spec:** P2-PAGE-007
- **Touches (new):** `src-tauri/src/pdf/split.rs`, `src/app/SplitDialog.tsx`,

- **What:** Four modes — (a) every N pages, (b) at specific page numbers, (c) by file-size target, (d) by top-level bookmarks. Each emits N output files.

- **Test:** `src-tauri/tests/split.rs` — each of the four modes.
