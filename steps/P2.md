# Phase 2 — Page operations (decoupled steps)

> Goal (per `docs/05_ROADMAP.md`): move, copy, delete, merge, split,
> extract, rotate pages — and finally **save real PDFs as output**.
>
> Phase 2 is also where the project earns the right to mutate bytes.
> Every write path lands behind the document actor and round-trips
> through PDFium before returning success — see [[B1]] in `steps/P1.md`.

## Acceptance demo (from roadmap)

- Open `tests/fixtures/acceptance/p2-multi.pdf`, delete page 3, insert a blank, rotate page 5 by 90°, save. Re-open in Adobe Acrobat: changes are visible, file is not corrupt.
- Merge 5 PDFs from `tests/fixtures/acceptance/p2-merge-*.pdf`. Form fields and bookmarks survive.
- Split a 100-page PDF into 10 files. Each file opens cleanly.

## Spec coverage

`P2-PAGE-001` through `P2-PAGE-010` (10 spec lines). Plus 3 infrastructure steps (save, autosave, undo/redo) with no `P2-PAGE-*` ID.

## Track A — Persistence infrastructure (must land before any B/C/D step)

### P2.A1. `[x]` Save button
- **Status:** Done. Atomic temp+rename, `.bak` rotation, round-trip verify,
  dirty-flag no-op. `check` + `test` (70/70) + `test:rust` (incl. 3
  `save_noop` cases) green. Human verified the saved artifact opens cleanly in
  Preview + Acrobat + a third reader, and re-opens in VibePDF itself (clean
  GUI dev session, no panics; also exercised a real 4-page statement).
  Deviation from the doc below: the Cmd/Ctrl+S binding lives in a new
  `src/app/use-save.ts` hook (matching the `use-file-open.ts` pattern) rather
  than inline in `App.tsx`; save logic lives in `pdf/document.rs` (which
  `docs/04` already allocates to "Open, save, metadata") rather than a new
  `pdf/save.rs`.
- **Spec:** infrastructure
- **Touches (new):** `src-tauri/src/commands/save.rs`, `src/ipc/save.ts`
- **Touches (modify):** `src/app/App.tsx` (Cmd/Ctrl+S binding), `src-tauri/src/pdf/actor.rs` (`Message::Save { path }`)
- **What:** Write the current PDFium document to disk. If `path` matches the original, rotate the previous file as `<name>.bak` (kept for one save cycle only). Round-trip the saved bytes through PDFium before reporting success; reject on read-back failure.
- **Acceptance:** Open hello.pdf → save → file size and SHA-256 unchanged (no-op save is a no-op). Edit (via a later step) → save → re-open in PDFium externally, no parse errors.
- **Test:** `src-tauri/tests/save_noop.rs` — open, save, assert byte-identical (or at least PDFium-identical after canonicalization).
- **Depends on:** P1.B1 (real actor).

### P2.A2. `[~]` Auto-save + crash recovery
- **Status:** Machinery landed — `pdf/autosave.rs` (write/scan/discard +
  the 30s std-thread tick), actor `Autosave` message + dir/cleanup,
  `recovery_list`/`recovery_discard` commands, `use-recovery.ts` +
  `RecoveryDialog.tsx`. `check` + `test` (77/77) + `test:rust` (incl. 4
  `autosave` cases) green. `[~]` not `[x]` because the live loop is dormant
  until something makes a doc dirty: the autosave-only-when-dirty write and
  the "force-kill → relaunch → recover" acceptance demo land with **P2.B2
  (delete)**. Deviations from the doc: the tick is a dedicated **std thread**
  (not `tokio::time` — that feature isn't enabled); autosave logic lives in
  `pdf/autosave.rs`; recovery "Recover" reopens the autosave file (adopting
  the *original* path so ⌘S targets it is a noted BACKLOG refinement).
- **Spec:** infrastructure
- **Touches (new):** `src-tauri/src/pdf/autosave.rs`, `src-tauri/src/commands/recovery.rs`
- **Touches (modify):** `src-tauri/src/lib.rs` (spawn the 30s tick task)
- **What:** Every 30 s, if the document is dirty, write a copy to `<app_data_dir>/autosave/<documentId>.pdf`. On startup, scan that dir; for each entry, offer a recovery dialog ("Recover unsaved changes to foo.pdf?").
- **Acceptance:** Edit a doc, force-kill the app, relaunch → recovery dialog appears. Accept → unsaved edits restored.
- **Test:** `src-tauri/tests/autosave.rs` — simulate dirty doc, advance time, assert file written; simulate crash by reusing the autosave dir; assert recovery payload matches.
- **Depends on:** P2.A1.

### P2.A3. `[~]` Undo/redo stack
- **Status:** Machinery landed — generic `UndoStack<T>` + `Edit<T>` command
  pattern (`pdf/undo.rs`, 4 unit tests), actor `Undo`/`Redo`/`GetHistoryState`
  messages, `pdf_undo`/`pdf_redo`/`pdf_history_state` commands,
  `history-store.ts` + `use-history.ts` (Cmd/Ctrl+Z, Cmd/Ctrl+Shift+Z),
  Undo/Redo toolbar buttons. `check` + `test` (76/76) + `test:rust` green.
  `[~]` not `[x]` because the acceptance as written ("delete pages 3,5,7 →
  undo") needs a real page op: it lands end-to-end with **P2.B2 (delete)**,
  which adds the first `Edit<PdfDocument>`. Until then the stack is always
  empty and undo/redo are verified no-ops. Architecture documented in
  `docs/04` § "Undo/redo (session history)".
- **Spec:** infrastructure
- **Touches (new):** `src-tauri/src/pdf/undo.rs`, `src/state/history-store.ts`
- **Touches (modify):** `src-tauri/src/pdf/actor.rs` (every mutating message pushes an inverse onto the stack)
- **What:** Per-document undo stack with **page-level** granularity (move, insert, delete, rotate, crop, resize each as one undoable action). Cmd/Ctrl+Z / Cmd/Ctrl+Shift+Z.
- **Acceptance:** Delete pages 3, 5, 7 → undo three times → all pages restored in correct order. Redo three times → same deletions reapplied.
- **Test:** `src-tauri/tests/undo_redo.rs` — sequence of mutations on hello.pdf, undo to start, assert page tree identical.
- **Depends on:** P2.A1.

## Track B — Single-page operations

### P2.B1. `[~]` Rotate page(s)
- **Status:** Landed — the first real edit. `RotateEdit: Edit<PdfDocument>`
  (`pdf/rotate.rs`) sets PDFium `/Rotate`, integrates with undo (A3) + dirty
  (A1/A2); actor `RotatePages` message; `pdf_rotate_pages` command; thumbnail
  right-click `RotateMenu` with live thumbnail refresh (cache-invalidate +
  re-render) and Undo-button sync. `check` + `test` (81/81) + `test:rust`
  (rotate.rs: 4 — persist/undo/redo/atomic-on-error) green. `[~]` not `[x]`
  until the human confirms `/tmp/vibepdf-verify-rotated.pdf` (also on the
  Desktop) renders rotated in Acrobat + Preview + a third reader.
- **Surfaced + fixed a real concurrency bug:** PDFium isn't thread-safe across
  documents (page-ops/save/close raced → SIGABRT/SIGSEGV). Unified all PDFium
  FFI under one process-global `PDFIUM_LOCK` (was render-only), close the
  actor's doc under it, and run the Rust tests single-threaded. See `docs/04`.
- **Deferred (BACKLOG):** live **main-view** preview of edits (PDF.js updates
  on save/reopen only) + undo/redo-driven view refresh — the shared
  "edit-preview pipeline" for all of B2–B5.
- **Spec:** P2-PAGE-001
- **Touches (new):** `src-tauri/src/pdf/rotate.rs`, `src/tools/rotate/`
- **Touches (modify):** `src/panels/ThumbnailPanel.tsx` (context-menu entry)
- **What:** Rotate single page, range, or all pages by 90° / 180° / 270°. Persisted as PDFium `/Rotate` on the page dict, not a viewer transform.
- **Acceptance:** Rotate page 1 of hello.pdf 90° → save → open externally in Preview.app → page renders rotated. Reopen in VibePDF → rotation persisted.
- **Test:** `src-tauri/tests/rotate.rs` — rotate, save, re-open, assert `/Rotate` on page 0.
- **Depends on:** P2.A1, P2.A3.

### P2.B2. `[ ]` Delete page(s)

## Track C — Multi-page operations

### P2.C1. `[ ]` Reorder via thumbnail drag
- **Spec:** P2-PAGE-002
- **Touches (modify):** `src/panels/ThumbnailPanel.tsx`, `src-tauri/src/pdf/reorder.rs` (new)
- **What:** Drag-drop within the thumbnail panel calls `pdf_reorder_pages`. Backend renumbers pages and updates all internal references (links, bookmarks, named destinations).
- **Acceptance:** Drag page 1 to the end of a 5-page doc → save → re-open → original page 1 is now page 5; bookmark that pointed to old page 1 now points to new page 5.
- **Test:** `src-tauri/tests/reorder.rs`.
- **Depends on:** P2.A1, P2.A3, P1.D1 (thumbnails panel must exist).

### P2.C2. `[ ]` Extract pages to new PDF
- **Spec:** P2-PAGE-006
- **Touches (new):** `src-tauri/src/pdf/extract.rs`, `src/ipc/extract.ts`
- **What:** Produce a new PDF containing the selected pages, copying or referencing all required resources (fonts, images, color spaces).
- **Acceptance:** Extract pages 2-3 of a 10-page PDF with embedded fonts → resulting file opens cleanly in Acrobat with no missing-glyph rendering.
- **Test:** `src-tauri/tests/extract.rs` — extract pages, open output via PDFium, assert page count + resource integrity (no dangling indirect refs).
- **Depends on:** P2.A1.

### P2.C3. `[ ]` Split (4 modes)
- **Spec:** P2-PAGE-007
- **Touches (new):** `src-tauri/src/pdf/split.rs`, `src/app/SplitDialog.tsx`
- **What:** Four modes — (a) every N pages, (b) at specific page numbers, (c) by file-size target, (d) by top-level bookmarks. Each emits N output files.
- **Acceptance:** Split a 100-page PDF every 10 pages → 10 files, each opens cleanly. Split by file-size target of 5MB on a 50MB PDF → expected output count.
- **Test:** `src-tauri/tests/split.rs` — each of the four modes.
- **Depends on:** P2.C2.

### P2.C4. `[ ]` Merge multiple PDFs
- **Spec:** P2-PAGE-008
- **Touches (new):** `src-tauri/src/pdf/merge.rs`, `src/app/MergeDialog.tsx`
- **What:** Concatenate N PDFs preserving annotations, form fields, bookmarks. On form-field name collision, suffix `_2`, `_3`, etc. Resulting bookmarks remain navigable.
- **Acceptance:** Merge 5 PDFs each with bookmarks and form fields → resulting file has all bookmarks (one tree per source) and all form fields with collision-free names.
- **Test:** `src-tauri/tests/merge.rs`.
- **Depends on:** P2.A1.
