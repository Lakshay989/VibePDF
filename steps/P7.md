# Phase 7 — OCR & conversion (decoupled steps)

> Goal (per `docs/05_ROADMAP.md`): scanned PDFs become searchable.
> PDFs convert to other formats and back.

## Acceptance demo (from roadmap)

- OCR a 30-page scanned manual → searchable PDF, visual layout unchanged.
- Convert a report.pdf to DOCX → headings are headings, tables are tables, images present.
- Compress 200MB of scans to <30MB with no visible quality loss at 100% zoom.

## Spec coverage

`P7-OCR-001` through `P7-OCR-011` (11 spec lines). Plus 1 infrastructure step.

## Tooling decision (settled 2026-09-21, in P7.A1)

`leptess` was stale — no release since 2023-02-21 — so Track A uses **`tesseract-rs` 0.4.0** with `build-tesseract`, which compiles Tesseract 5.5.2 and Leptonica 1.87.0 from source and links them statically: nothing for a user to install, one story on all three platforms. Its build script downloads sources and language data unverified, so `scripts/fetch-tesseract-src.sh` pre-places checksum-pinned copies and the build fetches nothing. Reasoning and the options rejected are in `docs/03_TECH_STACK.md`.

**First build after a fresh clone takes several minutes** (it is compiling a C++ OCR engine); later builds are cached in `~/Library/Application Support/tesseract-rs` (macOS) or `~/.tesseract-rs`.

## Track A — OCR

### P7.A1. `[ ]` Tesseract integration + preprocessing pipeline
- **Spec:** P7-OCR-003, plus the engine the rest of Track A needs
- **What:** English data (`tessdata_fast`, ~4 MB — not the ~15 MB `best` models) fetched and bundled. Image pipeline: despeckle, deskew, upscale to ≥300 DPI when input is lower, each switchable.
- **Touches:** `src-tauri/src/ocr/{mod,engine,preprocess,tessdata}.rs`, `scripts/fetch-tessdata.sh`, `scripts/fetch-tesseract-src.sh`.
- **Test:** `src-tauri/tests/ocr_smoke.rs` against `tests/fixtures/basic/scan.pdf` (a page that is only a picture of text), plus unit tests per preprocessing stage.
- **Depends on:** none. Tooling decision settled above.

### P7.A2. `[ ]` OCR a scanned PDF → searchable PDF
- **Spec:** P7-OCR-001
- **What:** Per page: render → OCR → the words written back as invisible text (`3 Tr`) over the ink they came from, in the page's own space so `/Rotate` and `CropBox` hold. One undoable edit; a protected document is refused like any other lopdf-backed edit.
- **Touches:** `src-tauri/src/pdf/ocr_text_layer.rs`, `actor.rs` (`RunOcr`), `commands/pdf.rs` (`pdf_ocr_run`), `src/ipc/ocr.ts`.
- **Test:** `src-tauri/tests/ocr_to_searchable.rs` against `scan.pdf`, `scan-rotated.pdf`, `scan-skewed.pdf`.
- **Not in this step:** any UI, progress reporting, parallel pages. ~4.5 s/page at 300 DPI, and the actor is single-threaded per document.
- **Depends on:** P7.A1.

### P7.A3. `[ ]` Language packs
- **Spec:** P7-OCR-002
- **What:** All twelve spec languages bundled (~25 MB, checksum-pinned). A thirteenth arrives from a file or by download — the app's only network call, off by default, user-initiated, and refused unless Tesseract can load what arrives. The invisible text layer now embeds a covering face, so the eight non-WinAnsi languages actually write text.
- **Touches:** `src-tauri/src/ocr/languages.rs`, `commands/languages.rs`, `pdf/ocr_text_layer.rs`, `scripts/fetch-tessdata.sh`, `src/ipc/languages.ts`.
- **Test:** `src-tauri/tests/ocr_languages.rs`, including a Russian scan read end to end.
- **Not in this step:** any UI, including the preprocessing toggles the original note mentioned — there is still no OCR surface to put them on.
- **Depends on:** P7.A1.

### P7.A4. `[ ]` The OCR surface
- **Spec:** the surface for P7-OCR-001/002/003 — no new spec line. Added 2026-09-23, because Track A built an engine nothing in the app could reach, and the phase's own acceptance demo ("open the scanned manual, run OCR") could not be performed.
- **What:** a **Read text…** toolbar entry and a dialog: language, whole document or this page, the three quality switches (which is where P7-OCR-003's "configurable" finally surfaces), and a Manage-languages section for adding a pack from a file, removing an added one, and the download switch.
- **Touches:** `src/app/OcrDialog.tsx`, `src/app/ZoomToolbar.tsx`, `src/view/PdfViewer.tsx`. Frontend only; no new Rust.
- **Test:** `src/app/__tests__/OcrDialog.test.tsx`.
- **Not in this step:** per-page progress (the backend reports nothing mid-run, so the dialog states the expected duration instead of animating a lie), cancelling a run, and detecting which pages need OCR.
- **Depends on:** P7.A1–A3.

## Track B — Conversions out (PDF → ...)

### P7.B1a. `[ ]` PDF → DOCX: text, formatting, headings, images
- **Spec:** P7-OCR-004 (**partially** — tables are P7.B1b)
- **What:** A `.docx` written directly: five XML parts in a hand-written ZIP container (`pdf/ooxml.rs`), with zero new crates — `flate2` and `crc32fast` were already reachable, while the `zip` crate is only a build dependency of the Tauri bundler. Reading order is **not** reimplemented: `export_text::group_pieces` was refactored to return indices rather than text so both exporters share one implementation of it. Headings are relative — the body size is whichever size the most *characters* use, and a line materially larger is a heading, ranked by size; a single-size document gets none.
- **Touches:** `src-tauri/src/pdf/{export_docx,ooxml}.rs`, `export_text.rs` (the `group_pieces` refactor), `actor.rs` (`ExportDocx`), `commands/pdf.rs` (`pdf_export_docx`), `src/ipc/export-docx.ts`, an **Export to Word…** toolbar entry.
- **Test:** `src-tauri/tests/export_docx.rs` — every test unzips the output and reads the XML, and one shells out to `unzip -t` so an implementation we did not write validates the container. Plus unit tests for the ZIP records, XML escaping, body-size and heading rules, and EMU conversion.
- **Known limits:** fonts are named, not embedded; columns become sequential blocks rather than Word columns; lists stay literal text; no footnotes, hyperlinks, colour, or headers/footers.
- **Depends on:** P4.A1 (text run extraction), P7.B3 (reading order).

### P7.B1b. `[ ]` PDF → DOCX: tables
- **Spec:** the rest of P7-OCR-004 — "table structures where detectable". **With this, P7-OCR-004 is complete.**
- **What:** Ruled grids become `<w:tbl>`. Rules are read from each path object's segments, **through the object matrix** — measured 2026-09-23, `PDFium` reports segment points *before* the matrix while bounds are *after*, so the raw points mislocate every rule in a transformed document. Four guards keep ordinary pages table-free: ≥2 horizontals and ≥2 verticals, lines that bound a region, ≥2×2 cells, and text inside. A cell's text leaves the paragraph flow, so nothing is said twice.
- **Touches:** `src-tauri/src/pdf/table_detect.rs` (pure geometry), `export_docx.rs` (`Block::Table`, cell filling, `<w:tbl>`).
- **Test:** `src-tauri/tests/export_docx_tables.rs` + 13 unit tests on synthetic rectangles. The fixture has three pages — separate stroked rules, one multi-subpath grid, and a grid under a transform — plus decoy section rules.
- **Known limits:** unruled tables are paragraphs; no row spans (`vMerge`), no column spans (`gridSpan`), no cell shading or border styles, no nested tables; a table split across a page break is two tables.
- **Depends on:** P7.B1a.

### P7.B2. `[ ]` PDF → image (PNG / JPG / TIFF / WebP, 72-600 DPI)
- **Spec:** P7-OCR-005
- **What:** One image file per page, into a folder, named `{stem}-{n:03}.{ext}` by the page's **own** 1-based number — exporting page 5 alone gives `report-005.png`, because an image file *is* that page (a split file starts over at 1, which is why `split.rs` numbers by sequence instead). A DPI outside 72–600 is refused, not clamped.
- **Touches:** `src-tauri/src/pdf/export_image.rs`, `actor.rs` (`ExportImages`), `commands/pdf.rs` (`pdf_export_images`), `src/ipc/export-image.ts`, `src/app/ExportImageDialog.tsx`, an **Export images…** toolbar entry, `PageVirtualizer` (`getPageSize`, so the dialog can state the pixel size before the run).
- **Test:** `src-tauri/tests/export_image.rs` (every output decoded again, not just checked for existence) + pure unit tests in the module.
- **Known limits:** WebP is **lossless only** — `image` 0.25 ships the VP8L encoder and lossy needs the C `libwebp`. TIFF goes through the `tiff` crate rather than `image`'s wrapper, which hardcodes no compression (8.4 MB a page, measured). One file per page; multi-page TIFF is not offered.
- **Not in this step:** progress reporting, cancellation, transparent-background or grayscale/CMYK output, export to a zip.
- **Depends on:** P1.B3 (render-to-bitmap).

### P7.B3. `[ ]` PDF → plain text (UTF-8, reading order)
- **Spec:** P7-OCR-006
- **What:** Text rebuilt from run geometry — columns left to right, lines down each column — rather than PDFium's stream order, which merges two columns line by line (measured 2026-09-23 on `two-column.pdf`). Pages separated by a blank line; a scan exports as empty until OCR has run.
- **Touches:** `src-tauri/src/pdf/export_text.rs`, `actor.rs` (`ExportText`), `commands/pdf.rs` (`pdf_export_text`), `src/ipc/export-text.ts`, an **Export text…** toolbar entry.
- **Test:** `src-tauri/tests/export_text.rs` + pure ordering unit tests in the module.
- **Known limits:** geometric order only (a sidebar lands where it sits), right-to-left comes out visually ordered, hyphenation and ligatures unchanged.
- **Depends on:** P4.A1.

### P7.B4. `[ ]` PDF → HTML (semantic, images extracted to sibling folder)
- **Spec:** P7-OCR-007
- **What:** One self-contained `.html`: `<h1>`–`<h3>`, `<p>` with `<strong>`/`<em>`, ruled tables as `<table>`, in reading order. Images are written as PNGs to `<name>_files/` beside it (the name browsers use for "save page complete") and linked by a percent-encoded relative path, so `Q3 report #2.html` still links. No images, no folder. The structure is **not** rebuilt: `export_docx::document_blocks` was extracted so Word and HTML write the same blocks and cannot disagree on reading order, headings or tables. The page fetches nothing — inline CSS only, no fonts or scripts — so it opens offline. Images get `alt=""` (decorative): nothing knows what they show, and an invented description is worse than none.
- **Touches:** `src-tauri/src/pdf/export_html.rs`, `export_docx.rs` (`document_blocks` extracted), `actor.rs` (`ExportHtml`), `commands/pdf.rs` (`pdf_export_html`), `src/ipc/export-html.ts`, an **Export to HTML…** toolbar entry. In passing: `src/ipc/export-docx.ts` gained the `tables` field it was missing.
- **Test:** `src-tauri/tests/export_html.rs` (13) on the Word fixtures — headings by level, emphasis, escaping, links that resolve on disk, a name with a space and `#`, no folder without images, an existing folder's other files left alone, tables, reading order, the PDF untouched — plus `xmllint --html` as the outside parser. Unit tests for escaping of markup-looking text, link encoding, and that the page references nothing external. Mutation-checked; the DOCX suites guard the extraction.
- **Known limits:** structure, not layout — no positioning, fonts or colours; no page breaks; links and lists stay text (as in Word); an earlier, longer export can leave stale `image-NNN.png` files in the folder.
- **Depends on:** P4.A1, P7.B1a/B1b (the block model).

### P7.B5. `[ ]` PDF → XLSX
- **Spec:** P7-OCR-008
- **What:** One sheet a detected table, named `Page N Table M`. Numbers become numeric cells **only when unambiguous** — `412,000` stays text, because a comma is a thousands separator in one locale and a decimal point in another and a PDF carries no locale. No tables means **no file**, which is the spec's warning case.
- **Touches:** `src-tauri/src/pdf/export_xlsx.rs`, `page_content.rs` (lifted out of `export_docx` so both exporters share one page reading), `actor.rs` (`ExportXlsx`), `commands/pdf.rs` (`pdf_export_xlsx`), `src/ipc/export-xlsx.ts`, an **Export to Excel…** toolbar entry.
- **Test:** `src-tauri/tests/export_xlsx.rs` + unit tests for the numeric/text decision, column letters, and sheet-name sanitising and de-duplication. The DOCX suites are the guard on the lift.
- **Known limits:** only ruled tables (inherited from P7.B1b); no merged cells, column widths, number formats, styling or formulas; grouped numbers stay text.
- **Depends on:** P7.B1b.

## Track C — Other conversions

### P7.C1. Create PDF from files (DOCX / images / TXT / HTML) — split 2026-10-18
- **Spec:** P7-OCR-009 — "preserve content, embed fonts, and produce a PDF/A-compatible output when the user requests it."
- Four steps of different size, like B1a/B1b. C1a builds the shared machinery; C1b and C1c each need a parser dependency (decided when reached); C1d needs a bundled ICC profile and an outside validator.

### P7.C1a. `[ ]` Images and plain text → PDF
- **Spec:** P7-OCR-009 (images, TXT; fonts embedded)
- **What:** One page per image, scaled to fit inside 36 pt margins (down, never up), centred, landscape when the image is wider than tall; A4 / Letter / "match each image" (1 px = 1 pt). **JPEG goes in byte for byte** as `DCTDecode` — no re-compression — with EXIF orientation applied by the placement matrix (all eight cases), and Adobe CMYK JPEGs given `/Decode [1 0 …]` so they are not inverted. PNG (via the `png` crate already shipped), TIFF and WebP are decoded and stored losslessly, transparency as a soft mask; over 100 MP is refused. Text is laid out at 10/12 pt with 0.75 in margins (an 80-column line fits A4) in an embedded, subset CID font — a monospaced system face (Menlo) when it covers every character, else the broad-coverage face — wrapped at spaces, between CJK characters, or mid-word when a word is longer than the line; tabs to 8-column stops; form feed starts a page. UTF-8 / UTF-16 by BOM, else Windows-1252 with a warning. A character no font covers is refused by name. Built with lopdf, saved through `save_document` (temp, reopen, rename).
- **Touches:** `src-tauri/src/pdf/create.rs`, `font_resolver.rs` (`broad_coverage_font_paths` made crate-visible), `commands/pdf.rs` (`pdf_create_from_files`, standalone like merge), `src/ipc/create.ts`, `src/app/CreatePdfDialog.tsx`, a **Create PDF…** button in the app header (works with no document open; the result is opened).
- **Test:** `src-tauri/tests/create_pdf.rs` (16): PDFium renders the output and pixels are sampled (colours, placement, transparency, all eight EXIF orientations checked against `image`'s own `apply_orientation`, a Ghostscript-made CMYK JPEG staying red); PDFium **and Ghostscript** extract the text and it matches the source; lopdf confirms the JPEG stream is byte-identical and every font has a `FontFile2`. Refusals: unsupported file (by name, nothing written), uncovered character, empty input. 9 unit tests (JPEG header, page fitting, wrapping, CJK, tabs, pagination, encodings). `CreatePdfDialog.test.tsx` (7). Mutation-checked: 10 of 10 killed.
- **Known limits:** no GIF/BMP (the `image` crate is built without them); 16-bit images reduced to 8-bit; PNG EXIF orientation ignored; one font per text file, so mixing scripts no single face covers is refused rather than split across fonts; a CJK line breaks anywhere, without kinsoku rules.
- **Depends on:** P4.HF (CID font embedding).

### P7.C1b1. `[ ]` DOCX → PDF: text, formatting, styles, lists, images
- **Spec:** P7-OCR-009 (Word documents; fonts embedded)
- **What:** The body in order: each run's font, size, bold/italic/underline/strike, colour, caps, super/subscript; paragraph alignment (incl. justified), indents, spacing, line spacing; styles through `basedOn` chains and document defaults; theme fonts; list numbering and bullets (Symbol/Wingdings private-use bullets mapped to Unicode); inline images at their size; the document's own page size and margins. Descends into hyperlinks, content controls and fields (the saved result, not the code); tracked changes shown accepted. **Simplified, with a warning each:** tables (as their cells' paragraphs, until C1b2), text boxes (after their anchoring paragraph), floating images (inline), equations (as text), multiple columns (as one); headers, footers, footnotes and comments left out. Faces are real: `font_index` finds bold/italic faces by family from each font's own name table (only a few KB read per file; 0.2 s for all of macOS's fonts, once) — including Mac-platform names, which macOS's Times has and nothing else; a missing family is substituted within its class (sans/serif/mono) and reported; a character the face lacks comes from an installed face of the same class and style first (Didot's missing Cyrillic from Times New Roman, not a sans), then the broad-coverage face. Layout (`flow.rs`) measures with the same advances the embedded `/W` is written from, joins touching pieces into one text operation, and embeds each face once, subset to the characters it drew, under its real PostScript name. The ZIP reader now uses the central directory (data descriptors) and caps inflated size.
- **Touches:** `src-tauri/src/pdf/{docx_read,flow,font_index,xml_tree}.rs` (new), `ooxml.rs` (`ZipArchive`), `font_embed_cid.rs` (collection index, PostScript names), `create.rs` (Word sources; `embed_image` shared), `Cargo.toml` (`quick-xml` 0.39, already in the build via Tauri), the create dialog (Word files).
- **Test:** `src-tauri/tests/create_docx.rs` (19): order and text; bold/italic in the real faces (`Arial-BoldMT` …); style chains; alignment incl. justified to the margin; bullets and numbers with nested levels; page size and margins; page breaks; flow onto more pages; an inline image's pixels where its extent says; substitution reported; fallback faces (same class first; broad face for CJK); tracked changes, field codes, hidden text; tables flattened with a warning; every font embedded; a damaged file refused by name. Outside writers: the `textutil` fixture (text via PDFium and Ghostscript, faces, centring, list indents) and a round trip through VibePDF's Word export (headings, image). Unit tests for the XML tree, ZIP reader (data descriptor, inflate cap), font index, numbering formats. Mutation-checked: 16 single mutations killed; two equivalent ones (deletions and field codes are blocked twice over) killed as a double mutation.
- **Known limits:** layout follows real glyph widths but not Word's kerning, hyphenation or leading, so lines can break a word earlier or later; custom tab stops use the 0.5 in defaults; no right-to-left; fonts embedded inside the DOCX aren't used.
- **Depends on:** P7.C1a.

### P7.C1b2. `[ ]` DOCX → PDF: tables
- **What:** Real table layout — column widths from `w:tblGrid`, cell text wrapped to its column, borders, rows split across pages — in place of C1b1's flattened cells.

### P7.C1c. `[ ]` HTML → PDF
- **What:** The same block structure from HTML. **Needs a decision:** an HTML parser (suggested: `html5ever`) or the system web view's print-to-PDF.

### P7.C1d. `[ ]` PDF/A output option
- **What:** XMP metadata, an sRGB `OutputIntent`, all fonts embedded (C1a already does), no encryption. **Needs a decision:** a bundled ICC profile (licence) and an outside validator for the tests (veraPDF, a Java download).

### P7.C2a. `[ ]` Compress
- **Spec:** P7-OCR-010 (**partially** — see "Not in this step")
- **What:** Three levels, chosen from measurement rather than from adjectives. Measured 2026-09-23 on a 20-page 300 DPI grayscale scan with sensor noise (81.6 MB): **low** keeps every pixel at JPEG q85 (20.4%), **medium** reduces to 200 DPI (9.1%), **high** to 150 DPI at q60 (1.5%). Stream deflation is the other half and has the opposite shape — nothing on a scan, 92.8% on `unicode-text.pdf`, which stores its font uncompressed. Writes a **new file**: the image pass is lossy, and an edit would let the next Ctrl-S destroy the original.
- **Touches:** `src-tauri/src/pdf/compress.rs`, `actor.rs` (`CompressDocument`), `commands/pdf.rs` (`pdf_compress_document`), `src/ipc/compress.ts`, `src/app/CompressDialog.tsx`, a **Compress…** toolbar entry, `PdfViewer` (size via PDF.js `getDownloadInfo`).
- **Test:** `src-tauri/tests/compress.rs` + unit tests for every eligibility rule. The ratio tests need `noisy-scan.pdf`, which is gitignored (~28 MB); they skip with a printed regenerate instruction when it is absent, and the correctness tests run on the committed fixtures regardless.
- **Known limits:** `/Indexed`, `/Separation`, `/DeviceN`, CMYK, 1-bit bilevel, JPEG 2000 and masked images are passed through untouched — in each case a lossy re-encode would change what the page *means*, not just how precisely it says it. The DPI estimate uses the page width rather than the drawn width, which under-shrinks images placed small and never over-shrinks them.
- **Not in this step:** **font subsetting**, the third target P7-OCR-010 names (deferred by decision 2026-09-23 — it needs a full content-stream walk to learn which glyphs are used, and saves nothing on scans). Also: object streams and xref streams (lopdf can read `/ObjStm` but not write it), JBIG2/JPX re-encoding, colour→grayscale conversion, and batch compression.
- **Depends on:** none.

### P7.C2b. `[ ]` Linearize ("optimize for web")
- **Spec:** P7-OCR-011
- **What:** Fast Web View — page-1 objects first, a linearization parameter dictionary, page-offset and shared-object hint tables, and two cross-reference sections.
- **Needs a decision before any code.** Neither library can do this. `PDFium` only *detects* linearization (`FPDFAvail_IsLinearized`); `lopdf` has no support and its `ObjectStream` is read-only. The options are hand-rolling it (qpdf spends ~2000 lines of C++, and the offsets are circular — the dictionary's own length changes the offsets it contains) or binding `libqpdf`, a C++ system library, which is the exact property `tesseract-rs` already strains. It is also the lowest-value item in Phase 7 for an offline editor: Fast Web View pays off when a file is byte-range-served to a browser.
- **Depends on:** none.

### P7.C2c. `[ ]` Font subsetting
- **Spec:** the remaining third of P7-OCR-010
- **What:** Walk every content stream, track font resources through `Tf`, collect the character codes actually used, map them through the encoding/CMap to glyph IDs, subset with the `subsetter` crate already in the tree, and rewrite the font dictionary and encoding.
- **Depends on:** P7.C2a.
