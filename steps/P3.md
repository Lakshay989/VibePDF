# Phase 3 — Annotations (decoupled steps)

> Goal (per `docs/05_ROADMAP.md`): standard PDF annotations that
> round-trip through Acrobat, iOS Books, and Okular.

## Acceptance demo (from roadmap)

- Add five annotations of different types to `tests/fixtures/acceptance/p3-doc.pdf`. Save. Open in Acrobat Reader, iOS Books, and Okular. All five render correctly in all three.
- Open `tests/fixtures/acceptance/p3-annotated.pdf` (annotated in Acrobat) — every annotation shows in our sidebar with correct authors and timestamps.
- Export to XFDF → delete all annotations → re-import the XFDF → annotations restored identically.

## Track A — Annotation infrastructure

### P3.A1. `[~]` Annotation tool framework
- **Status:** Landed (frontend-only infra, no PDF surface). `src/tools/_framework/`
  ships the **tool contract** (`AnnotationTool`: stateless pointer-gesture
  reducers), a **pure lifecycle state machine** (`lifecycle.ts`:
  idle→drawing→commit/cancel, threads the draft), **screen↔PDF coordinate
  mapping** (`coords.ts`, all 4 rotations + y-flip), a tool **registry**, and an
  `example-rect-tool` used only to exercise the lifecycle in tests. State: new
  `useToolStore` (active tool + style options) and `useAnnotationStore` (per-doc
  draft + committed annotations) — both **frontend preview layers**, not a source
  of truth (the actor persists in B1). `check` + `test` (160/160, incl. lifecycle
  5 / coords 4 / annotation-store 5) green. No Rust, **no IPC** (annotations
  don't touch bytes until B1). `[~]` not `[x]`: pure infra with **no
  user-visible demo** — it's first exercised end-to-end by **A2 (render layer) +
  B1 (highlight)**; flip to `[x]` then, or now on the strength of the unit tests.
- **Spec:** infrastructure
- **Touches (new):** `src/tools/_framework/{types,tool-contract,coords,lifecycle,registry,example-rect-tool,index}.ts` (+ `__tests__/`), `src/state/{tool-store,annotation-store}.ts` (+ `__tests__/`); (modify) `docs/04_ARCHITECTURE.md` (store table + framework note).
- **What:** Common lifecycle for every annotation tool — `activate → pointerdown → pointermove → pointerup → commit/cancel`. Each concrete tool plugs in via the contract in `04_ARCHITECTURE.md §Edit tools`. **Pointer events, not HTML5 DnD** (WKWebView; docs/04 §WebView quirks).
- **Test:** `src/tools/_framework/__tests__/{lifecycle,coords}.test.ts`, `src/state/__tests__/annotation-store.test.ts`.
- **Depends on:** none (realizes the `useToolStore` + `§Edit tools` contract docs/04 described but had not built).

### P3.A2. `[x]` Annotation render layer
- **Status:** Landed (frontend-only, no PDF surface — persistence is B1).
  `src/view/annotation-layer.tsx` is the per-page SVG overlay: draws committed
  annotations + the live draft (PDF→screen via A1 `coords`), and when a tool is
  active captures pointer events to drive the A1 lifecycle (`setPointerCapture`),
  committing into the store. Idle → `pointer-events:none` (click-through) except
  on shapes, so clicking a shape selects it without blocking scroll. Mounted in
  `PageVirtualizer`'s `PageSlot` via a **restructure**: the canvas now mounts into
  an inner div so the React overlay (a sibling) survives the imperative
  child-clear, while the **outer flow element stays registered for scroll** (the
  `offsetTop` jump-to-page fix is preserved). A **temporary** "▭" toolbar toggle
  (registers the A1 `example-rect-tool`) makes it eyeball-able — removed in
  B1/C1. `check` + `test` (164/164, incl. annotation-layer 4) green; no Rust,
  **no IPC**. Added a jsdom **PointerEvent polyfill** (`test-setup.ts`) so
  pointer-driven component tests get real `clientX/Y`. `[~]` until the human
  draws a preview rect in-app (then `[x]`, or fold into B1).
- **Spec:** infrastructure
- **Touches (new):** `src/view/annotation-layer.tsx` (+ `__tests__/`); (modify) `src/view/PageVirtualizer.tsx` (PageSlot restructure), `src/app/ZoomToolbar.tsx` (temporary toggle), `src/test-setup.ts` (PointerEvent polyfill).
- **What:** SVG layer mounted on top of each page canvas. Reads from `useAnnotationStore`, draws each annotation in its native PDF coordinate system. Hit-testing for select/edit. **Pointer events, not HTML5 DnD** (WKWebView).
- **Test:** `src/view/__tests__/annotation-layer.test.tsx`.
- **Depends on:** P3.A1, P1.C1 (virtual-scrolling page list).

## Track B — Text markup (read-only-content overlays)

### P3.B1. Highlight / underline / strikethrough / squiggly — split B1a / B1b
- **Spec:** P3-ANN-001. Split into **B1a** (selection + on-screen preview,
  frontend-only) and **B1b** (persist to PDF + `/AP` + cross-reader).

#### P3.B1a. `[x]` Text selection + markup preview (frontend, no persistence)
- **Human-verified (2026-06-15):** text is selectable and selection tracks the
  glyphs — but only after **three WKWebView text-layer fixes** (docs/04 "WebView
  quirks"): a `ReadableStream` async-iterator polyfill (`src/polyfills.ts`, else
  `getTextContent` throws), porting the **full** v5 `.textLayer` CSS (span
  `font-size`/`scaleX` — without them a click selects the whole page), and pinning
  an explicit px layer size (CSS `round()` may be unsupported). Plus
  `standardFontDataUrl`/`cMapUrl` in `getDocument` (assets copied by
  `scripts/copy-pdfjs-worker.mjs`). Also fixed: `getClientRects()` returns the
  text-layer's full-page rect → filtered out in `apply-markup` (was highlighting
  the whole page).
- **Status:** Landed. Added a **PDF.js text layer** (`src/view/text-layer.tsx`,
  `TextLayer` v5) over each page so text is **selectable** (mounted in `PageSlot`
  between canvas and the annotation overlay; `.textLayer` CSS in `globals.css`).
  Text markup is **selection-driven, not the A1 drag lifecycle**: a
  `MarkupToolbar` (Highlight/Underline/Strikethrough/Squiggly + colour) reads
  `window.getSelection()` and `apply-markup.ts` groups its line rects per page →
  `/QuadPoints` (`quads.ts`, pure) → one `MarkupAnnotation` per page in the
  store. The A2 overlay renders them (highlight = `mix-blend-mode: multiply`
  quads; underline/strike/squiggly = lines). **Preview-only — nothing is written
  to the PDF** (reload/save clears it; that's B1b). `check` + `test` (173/173:
  quads 4, apply-markup 3, annotation-layer markup +2) green. No Rust, **no IPC**.
  The temporary A2 "▭" toggle was removed (replaced by the markup toolbar; the
  example-rect-tool stays for C1 + its tests). `[~]` until the in-app selection +
  preview check.
- **Touches (new):** `src/view/text-layer.tsx`, `src/tools/text-markup/{quads,apply-markup}.ts` (+ tests), `src/app/MarkupToolbar.tsx`; (modify) `src/tools/_framework/types.ts` (`MarkupAnnotation`), `src/view/annotation-layer.tsx` (markup rendering), `src/view/PageVirtualizer.tsx` (text layer + geometry data-attrs), `src/view/PdfViewer.tsx` + `src/app/ZoomToolbar.tsx` (toolbar swap), `src/styles/globals.css`.
- **Depends on:** P3.A1, P3.A2.

#### P3.B1b. `[x]` Persist text markup to the PDF (lopdf + `/AP` + cross-reader)
- **Human-verified (2026-06-15):** in-app select-text → Highlight → the highlight
  renders on the text in the main view (PDF.js draws the `/AP`), ⌘Z removes it,
  ⌘S persists; the `/AP` is byte-verified + renders in Chrome. Required three
  WKWebView text-layer fixes to get selection working (see B1a + docs/04 "WebView
  quirks"). Also added a **Clear** button (`cos::clear_text_markup` /
  `ClearMarkupEdit` / `pdf_clear_text_markup`) — removes all markup in one
  undoable edit. Known polish (BACKLOG): overlapping highlights Multiply-blend
  into mixed colours; dark-mode recolours the baked-in highlight.
- **Status:** Landed. `cos::add_text_markup` (lopdf) appends the markup annot dict
  (`/Subtype` Highlight/Underline/StrikeOut/Squiggly, `/QuadPoints`, `/C`, `/CA`,
  `/Rect`, `/P`, `/F 4`) **+ a generated `/AP` form-XObject appearance** (highlight
  = `Multiply`-blended filled quads; underline/strike = lines; squiggly = zigzag)
  to the page `/Annots`. `pdf/annotation.rs::TextMarkupEdit` (byte-handoff; inverse
  = `RestoreDocEdit`); actor `AddTextMarkup`; `pdf_add_text_markup` command. The
  `MarkupToolbar` now **writes to the PDF via IPC** (no longer the store) → epoch
  reload → **the PDF.js canvas renders it from `/AP`** (the chosen rendering path).
  Undoable; `⌘S` persists. `check` + `test` (173/173) + `test:rust` (text_markup: 3
  + cos markup: 3) green; the artifact `Sample PDFs/vibepdf-verify-highlight.pdf`
  keeps `/Subtype/Highlight` + `/QuadPoints` + `/AP` through the PDFium save.
  `[~]` until the human confirms cross-reader (Acrobat/Preview/Chrome) **and** that
  the in-app PDF.js canvas shows the committed highlight (the rendering-decision

- **Limits (BACKLOG):** no optimistic preview (a brief delay between click and the
  reloaded highlight); `/QuadPoints` order verified visually; squiggly `/AP` is an

### P3.B2. Sticky notes (Text annotations) — split B2a / B2b
- **Spec:** P3-ANN-002. Split into **B2a** (place + icon + popup + edit + delete +
  persist, in-session) and **B2b** (read existing notes on open, so a reopened
  file shows its notes in-app).

#### P3.B2a. `[~]` Place / edit / delete a sticky note + persist
- **What:** A **Note** toggle in the markup toolbar arms the sticky-note tool;
  clicking the page drops a `/Text` annotation at that PDF point, shows an
  overlay icon, and opens a popup to edit the body. Save/Delete from the popup.
  Each action is a separate undoable actor edit; `⌘S` persists.
- **Status:** Landed. Backend is lopdf (`cos::add_text_note` / `update_text_note`
  / `delete_annotation` + `pdf_date_now` / `append_annotation` /
  `find_annotation_by_nm`); the note dict is `/Subtype /Text`, `/Contents`, `/T`
  (author), `/NM` (stable id = the store id), `/M` + `/CreationDate`, `/Name
  /Note`, `/C [1 0.82 0]`, `/F 28` (Print|NoZoom|NoRotate), `/Open false`, and
  **deliberately no `/AP`** — readers draw the icon from `/Name`, so we avoid a
  canvas/overlay double-draw. `pdf/annotation.rs` adds a shared `cos_edit` helper
  + `AddNoteEdit` / `UpdateNoteEdit` / `DeleteAnnotationEdit` (byte-handoff;
  inverse = `RestoreDocEdit`); actor `AddNote` / `UpdateNote` /
  `DeleteAnnotation`; commands `pdf_add_text_note` / `pdf_update_text_note` /
  `pdf_delete_annotation`.
- **Rendering decision:** unlike markup (canvas draws the `/AP`), notes have no
  `/AP`, so they are **overlay-rendered** by a new HTML `NoteLayer` (sibling of
  the SVG `AnnotationLayer`, mounted on top) from the annotation store. Placement
  persists immediately (store + PDF in lockstep from the first frame). `check` +
  `test` (185/185: notes IPC 4, note-tool 3, NoteLayer 5) + `test:rust`
  (text_note 4, cos note 2) green; artifact `Sample PDFs/vibepdf-verify-note.pdf`
  keeps `/Subtype/Text` + `/Contents` + `/NM` through the PDFium save.
- `[~]` until the human confirms in-app (place → type → Save → icon shows; reopen
  popup → edit; Delete; ⌘Z; ⌘S) **and** cross-reader (Acrobat/Preview/Okular show
  the note icon + body).
- **Limits (BACKLOG → B2b and beyond):** reopening a saved file does **not** yet
  show its notes in-app (the store is in-session only — that's B2b); placing then
  cancelling without typing leaves an empty note persisted; popup closes only via
  ✕ / Save / Esc (no outside-click); author is a fixed `"VibePDF User"` until
  per-user identity exists.
- **Touches (new):** `src/ipc/notes.ts`, `src/tools/sticky-note/note-tool.ts`,
  `src/view/note-layer.tsx`, `src/view/NotePopup.tsx`, `src-tauri/tests/text_note.rs`,
  and the matching `__tests__`; (modify) `cos.rs`, `annotation.rs`, `actor.rs`,
  `commands/pdf.rs`, `lib.rs`, `types.ts`/`index.ts`, `annotation-layer.tsx`,
  `example-rect-tool.ts`, `PageVirtualizer.tsx`, `MarkupToolbar.tsx`,
  `eslint.config.js`, `tests/cos.rs`.
- **Test:** `src-tauri/tests/text_note.rs`, `cos.rs`; frontend `notes`, `note-tool`,
  `note-layer`.
- **Depends on:** P3.A1, P3.A2.

#### P3.B2b. `[~]` Read existing notes on open (re-openable in-app)
- **What:** make the note overlay a **projection of the PDF**, not an in-session
  cache. A reopened (or session-restored) file shows its notes in-app, and an
  actor-level ⌘Z/⌘⇧Z no longer leaves a ghost icon.
- **Status:** Landed. `cos::read_text_notes` (inverse of `add_text_note`) returns
  a `NoteData { nm, page (0-based), x, y, content, author }` per `/Text` annot in
  page order; actor `ReadNotes` (read-only — serialize under the PDFium lock, then
  lopdf-parse, like `GetBytes`); command `pdf_read_text_notes`. Frontend
  `useNotesSync(documentId)` reads the notes and `replaceNotes` (a new store
  action that swaps only `note`-type annotations) whenever the **documentId** or
  the **edit epoch** changes — so it fires on open/restore/tab-switch AND after
  every reload-edit (undo/redo bump the epoch). Mounted in `App.tsx` beside
  `useHistory`. Placement does **not** bump the epoch, so the optimistic icon
  isn't clobbered before its write lands. A note authored elsewhere without `/NM`
  gets a synthesized `obj-<n>-<g>` id so it still renders. `check` + `test`
  (191/191: +`readTextNotes` 1, `replaceNotes` 1, `useNotesSync` 4) + `test:rust`
  (text_note: +4 read-back/undo-redo; cos: +2 read) green.
- `[~]` until the human confirms in-app: place a note → Save → ⌘S → **close +
  reopen the file** → the icon + body are back; and place → ⌘Z hides it → ⌘⇧Z
  restores it. (Reuse `Sample PDFs/vibepdf-verify-note.pdf` from B2a — no new
  write path, so no new artifact.)
- **Limits (BACKLOG):** `/CreationDate`/`/M` aren't parsed back, so `createdAt` is
  `0` (display is D1/sidebar); UTF-16BE/PDFDocEncoding `/Contents`/`/T` from other
  editors aren't decoded (we only guarantee round-trip of notes we wrote); the
  re-sync re-reads on *every* epoch bump (incl. markup edits) — a notes-only gate
  is a later optimization.
- **Touches (new):** `src/app/use-notes-sync.ts`, `src/app/__tests__/use-notes-sync.test.tsx`;
  (modify) `cos.rs` (`read_text_notes` + `NoteData`), `actor.rs`, `commands/pdf.rs`,
  `lib.rs`, `src/ipc/notes.ts`, `annotation-store.ts`, `App.tsx`, `tests/cos.rs`,
  `tests/text_note.rs`, `src/ipc/__tests__/notes.test.ts`, `annotation-store.test.ts`.
- **Test:** `src-tauri/tests/text_note.rs` (read-back, undo/redo), `cos.rs` (read);
  frontend `notes`, `annotation-store`, `use-notes-sync`.
- **Depends on:** P3.B2a.

### P3.B3. Free-text annotations — split B3a / B3b
- **Spec:** P3-ANN-003. Split into **B3a** (a box with one uniform style —
  family/size/colour/bold/italic) and **B3b** (rich text `/RC`+`/DS`, underline,
  auto-wrap, and re-edit of a committed box).

#### P3.B3a. `[~]` Free-text box, uniform style (family/size/colour/bold/italic)
- **What:** a **Text** toolbar toggle arms the free-text tool; drag a box on the
  page → a positioned `<textarea>` editor opens → type → **Add** commits. One
  uniform style picked from the toolbar (font family, size, colour, B/I).
  Undoable; `⌘S` persists.
- **Status:** Landed. Backend lopdf (`cos::add_free_text`): a `/Subtype /FreeText`
  dict (`/Rect`, `/Contents`, `/DA`, `/F 4`, `/P`) **plus a generated `/AP`** form
  XObject whose stream draws the text (`BT /F1 <size> Tf … TL <x> <y> Td (line)
  Tj T* … ET`) with a self-contained base-14 `/Font` resource (so display doesn't
  need an AcroForm `/DR`). Helpers `base_font` (12 base-14 names) + `pdf_escape`.
  `pdf/annotation.rs::FreeTextEdit` (byte-handoff; inverse `RestoreDocEdit`);
  actor `AddFreeText`; `pdf_add_free_text` command. `ToolOptions` gained
  `fontFamily`/`fontSize`/`bold`/`italic`.
- **Rendering decision (same as markup):** the committed box carries an `/AP`, so
  the **PDF.js canvas** draws it (write via IPC → `bumpEpoch` reload). The new
  `FreeTextLayer` holds **no committed boxes** — only the transient drag/preview +
  editor. `check` + `test` (201/201: addFreeText 2, free-text helpers 4,
  FreeTextLayer 4) + `test:rust` (free_text 3, cos free-text 4) green; artifact
  `Sample PDFs/vibepdf-verify-freetext.pdf` keeps `/Subtype/FreeText` + `/AP`
  through the PDFium save.
- `[~]` until the human confirms in-app (Text → drag → type → Add → the styled
  text renders **on the canvas**; ⌘Z removes; ⌘S persists) **and** cross-reader
  (Acrobat/Preview/Okular). The canvas-renders-`/AP` assumption is the key check —
  if PDF.js doesn't draw the FreeText `/AP`, fall back to overlay-render (the
  `FreeTextLayer` is ready for it), same posture as B1b.
- **Limits (BACKLOG → B3b):** no underline / rich `/RC` (mixed runs); no auto-wrap
  (explicit `\n` only); no re-edit of a committed box; base-14 / ASCII-WinAnsi
  only (no embedding, no non-Latin); `/DA` carries no AcroForm `/DR` (best-effort
  for appearance-regenerating readers; `/AP` is primary).
- **Touches (new):** `src/ipc/freetext.ts`, `src/tools/free-text/free-text.ts`,
  `src/view/free-text-layer.tsx`, `src-tauri/tests/free_text.rs`, and the matching
  `__tests__`; (modify) `cos.rs`, `annotation.rs`, `actor.rs`, `commands/pdf.rs`,
  `lib.rs`, `types.ts`/`index.ts`, `tool-store.ts`, `MarkupToolbar.tsx`,
  `PageVirtualizer.tsx`, `tests/cos.rs`, plus the two `ToolOptions` test fixtures.
- **Test:** `src-tauri/tests/free_text.rs`, `cos.rs`; frontend `freetext`,
  `free-text`, `free-text-layer`.
- **Depends on:** P3.A1, P3.A2.
